# 流媒体内容识别手册

视频、直播、音乐是动态内容：UI 树只有标题/评论/弹幕，静态截图只有一帧。
**只看标题、弹幕或评论不算看懂**；刷到值得理解的内容时，用一次 `phone_watch_media`
录一段正在播放的声音并抓关键帧，把「听到什么、看到什么」变成文字。

## 什么时候用

- 值得理解的内容：讲解/科普、剧情片段、新闻、直播在聊什么、音乐/歌名、游戏实况等
  只看标题判断不了的场景，调用一次（一般 15–30 秒；直播按当前话题决定）。
- 只是为了翻页、点赞、评论、找入口的普通浏览：继续用低层工具（`phone_swipe` /
  `phone_tap` 等）和 `phone_screen(mode="image")`，不要用 `phone_watch_media` 代替
  正常浏览与互动。
- **不要每条内容都识别**：标题+正文+评论已经说清楚的就不调用；同一段内容不要反复识别。

## 参数怎么选

- `seconds`：录制秒数。不传时用 `media.seconds`（默认 20）；短视频给 10–20，直播话题
  给 20–30；单次上限 `media.max_seconds`（默认 60）。
- `question`：想重点了解什么，例如「主播在讲解什么」「这首歌叫什么」「这段剧情讲了
  什么」；会拼进画面描述提示词，比泛泛描述更有用。
- `mode`：`auto`（默认）/ `audio`（只转写声音）/ `frames`（只描述画面）/
  `both`（声音与画面都识别）。只想听内容时用 `audio`，只想看画面时用 `frames`。

## 用法与结果

1. 确认设备正在播放目标内容（`phone_status` 看前台 App；需要时
   `phone_screen(mode="image")` 或 `phone_traffic` 确认）。
2. 调用一次 `phone_watch_media`，等工具返回（采集 + 转写 + 描述，耗时随秒数增加）。
3. 读返回的【媒体识别】（前台 App、观察/录音时长、关键帧数、总耗时）、【语音转写】、
   【画面描述】与降级说明：
   - 语音转写可能有错别字、同音词、歌词识别偏差；画面描述只覆盖抓到的几帧；
   - 结合标题/弹幕/评论交叉判断，拿不准就如实说「没完全听清/看清」。
4. 把听到、看到的内容用自己的话写进汇报，或 `phone_learn` 记录（source 写 App/页面/
   标题）；有长期记忆工具也写一条。识别结果只用于理解，不要照搬搬运受版权保护的内容。
5. 需要补充时换 `question` 再识别一次即可；**同一段不要反复识别**，避免浪费时间和额度。

## 降级与失败

- **无音频/近乎静音**：App 有 DRM/禁止播放捕获、设备静音、系统低于 Android 11 或音源
  不是 `output`。此时如实说明「只有画面，没有听清声音」，不要假装听到了。
- **语音转写为空**：STT Provider 未配置/超时，或内容本身没有语音（纯音乐/环境音）；
  检查 `media.asr_provider_id` 与 AstrBot 语音识别配置，或调大
  `media.asr_timeout_seconds`。
- **画面描述失败**：视觉 Provider 不可用/超时；配置 `media.vision_provider_id` /
  `perception.ocr_provider_id`，或调大 `media.vision_timeout_seconds`；也可自己
  `phone_screen(mode="image")` 看画面。
- **工具报错**：不要连续重试；先 `phone_status` 确认设备在线、内容在播放，失败就如实
  告诉用户当前只有标题/截图信息，不要编造内容。

## 边界

- 不要用它代替正常浏览、点赞、评论、发帖：互动仍先 `phone_interaction_gate` 申请，
  再用低层工具完成。
- 只采集设备播放的声音（`output`）；除非主人显式配置 `media.audio_source=mic`，否则
  不录麦克风/环境音；不要把录音文件用于识别以外的用途。
- 识别属于辅助理解：内容价值不高时跳过，别把每次浏览都变成一次录制。
