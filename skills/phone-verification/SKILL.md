# 人机验证 / 做题手册

遇到滑块、顺序点击、识图点击、拼图、答题/测试页时，**优先用 `phone_solve_verification`**
一次调用自动完成；它失败或需要手动精细控制时，再用 `phone_bypass_verify` 一次手势完成。
不要在验证页反复 `phone_screen(mode="ui")` 等 uiautomator dump（单次 2~13s），也不要
反复 `phone_wait` 干等，更不要连续盲目点击。

## 两阶段 solver 流程（phone_solve_verification）

一次工具调用内部完成两阶段视觉分析，避免主模型多轮截图/dump 超时：

1. **第一次截图 + 第一次视觉模型**：识别图片内容摘要、是否人机验证（以及类型：
   slider / sequence / image_click / puzzle / none）、是否答题/测试页；
2. 若既不是验证也不是做题：返回内容摘要与「未检测到验证码/答题」，可选附带截图；
   不需要继续操作；
3. 若是验证码或做题：**重新截图 + 第二次视觉模型**，要求给出操作顺序（点击序列或拖拽
   轨迹）与最终确认点（提交/下一题/确认按钮）；
4. **自动执行**操作顺序与确认点，再快速截图 + 读取执行后 UI 文本做结构化判定：挑战已解除 /
   答题进度 / 未通过 / 无法确认，结果写在工具返回里；
5. 全程保持一次工具调用，不需要你反复截图、dump 或等页面。

参数：

- `mode=auto|captcha|quiz`：默认 auto 自动判断；captcha/quiz 筛选实际检测类型，普通页面仅返回摘要；首次只读识别完成后才开始验证尝试计时；
- `include_image`：是否回传截图（默认 true）；
- `timeout_seconds`：每次视觉模型调用超时，0=用 `perception.verify_timeout_seconds`
  （默认 30s），再回退 `perception.ocr_timeout_seconds`；实际还会被单次尝试剩余时间
  （`verification.attempt_timeout_seconds`）收紧。

## 结果判定与暂停语义

- 工具结果会写清判定：**已解除**（挑战消失/答题完成）、**答题进度**（换到下一题，只累计
  已答题数、不计失败）、**未通过**（页面提示失败或挑战仍在）、**无法确认**（观察失败，
  按 fail-closed 计失败）；
- 失败次数达到 `verification.max_attempts` 或会话总时限到 → 进入人工协助：手机暂停，
  工具调用会被拒绝，等用户 `/phone verify resume <id>` 或 `/phone verify cancel <id>`；
- 人工等待超时后进入 `expired`：仍然暂停，`resume` 无效，必须由用户 `/phone verify cancel <id>`；
- 暂停/到期会取消在途求解，动作批次不会在暂停后继续点击；不要试图换工具绕过。

适用：滑块、顺序点击、识图、拼图、找相同、答题/测试/问卷页。视觉 Provider 不可用或
超时/识别失败时，工具会给出可操作建议，此时回退 `phone_bypass_verify` 手动完成。

## 做题 / 测试页

- 检测到答题/测试/问卷/验证页面时（工具结果会出现「检测到答题/验证页面」提示），先
  `phone_solve_verification(mode="quiz")`：它读题、给出选项点击顺序与提交/下一题坐标并
  自动执行，比多轮「截图→想→点」快；
- 逐题推进：solver 换题会返回「答题进度」并继续，不累计失败次数；每做完一题再截一张图
  确认页面变化，避免在旧坐标上连续点击；
- 判断题/多选题/填空题：solver 按截图给出的选项顺序点击；若页面要求手动输入文字，
  用 `phone_input_text` 配合 `phone_bypass_verify(capture)` 看清输入框位置；
- 需要自己看题决定时，用 `phone_bypass_verify(action="capture")` 截一张图，读懂后一次性
  `tap_points` 完成，不要反复 `phone_wait`/`phone_screen` 干等；
- 答题/测试可能有多页，注意确认点（下一题/提交）与最终提交按钮，不要提前交卷或漏交。

## 识别常见验证

- **滑块 / 拖拽**：页面出现「按住滑块向右拖动」「拖动到缺口」等提示，或出现
  `SeekBar`/`ProgressBar` 样式的横向条。标准横向滑块优先用 `slide`；带缺口拼图、需要
  按轨迹拖动的用 `drag`。
- **顺序点击 / 点选**：要求「按顺序点击文字」「依次点击图形」「点选所有符合条件的图」。
  用 `tap_points` 一次传入全部坐标，一次调用完成。
- **识图 / 拼图**：显示旋转/拼图/找相同图案，需要先看图再决定点击或拖拽位置。先
  `capture` 看清晰图，再 `tap_points` 或 `drag`。
- **文字/数字验证码**：不是手势验证，用 `phone_read_screen`（OCR/图片理解）识别后
  `phone_input_text` 输入；见 `phone-autonomy` 手册。
- **短信/邮箱验证码、人脸、实名认证**：这类需要用户本人操作，**不要尝试绕过**，直接
  如实告诉用户处理。

## phone_bypass_verify 四种动作（手动兜底）

| action | 用途 | 关键参数 |
| --- | --- | --- |
| `capture` | 快速截图（不跑 uiautomator dump，约 0.6s 级），先看清验证类型与坐标 | `include_image`（默认 true） |
| `drag` | 按坐标拖拽一次完成（滑块、拼图、任意拖拽） | `x1,y1,x2,y2`，`duration_ms`（默认 400） |
| `tap_points` | 顺序点击：一次调用按顺序点击多个点（顺序点击/点选文字/图形） | `points=[{x,y}, ...]`（1–12 个），`interval_ms`（默认 250） |
| `slide` | 自动在当前界面找滑块并拖到最右（标准横向滑块） | 无 |

所有动作都可带 `include_image=true`（默认）返回操作后的截图，便于校验。首次写操作需在当前页面读取到验证提示；纯图片挑战先用 solver 识别。普通按钮使用 phone_tap，普通拖动使用 phone_swipe。

## 手动推荐流程

1. **先 `capture` 快速截图**，看清验证类型、缺口位置、需要点击的目标（不要先 dump）。
2. 按类型选动作：
   - 标准横向滑块 → `slide`；
   - 拼图/任意轨迹拖拽 → `drag`，从截图读出起点与终点坐标；
   - 顺序点击 → `tap_points`，把要点的坐标一次传全（不要一次点一个反复调用）。
3. **一次动作后立即校验**：`capture` 或 `phone_screen(mode="image")` 看是否通过。
4. 失败最多再调整一次坐标/动作；仍失败就**停下**，把验证类型、当前页面和失败现象
   简要汇报给用户，不要连续重复点击或反复 dump。

## 坐标与分辨率

- 坐标基于当前屏幕分辨率（`phone_status` 可看分辨率），截图与手势使用同一套坐标；
  不要凭记忆填写旧坐标，每次以本次截图为准。
- 拿不准坐标时先 `capture` 再看图估算，避免盲目点击导致风控。

## 边界与安全

- 只用于自己账号的正常登录/操作验证，不做验证码破解、撞库或绕过账号安全。
- 短信/邮箱验证码、人脸核验、实名信息必须交用户处理；不要猜测或填充。
- 验证失败不要重复尝试超过 2 次：触发风控或锁定账号的代价远大于一次任务失败。
- 汇报时只说明「遇到什么验证/题目、尝试了什么、是否通过、失败原因」，不记录用户隐私内容。
